# 📋 תוכנית: זיהוי הקשר ותמונה של הפריט הרלוונטי

## המטרה
שהבוט יבין **פוסט שלם** ולא רק הודעה בודדת: הוא יחבר טקסט ותמונות שנשלחו בנפרד, יבין תגובות ("עדיין רלוונטי?"),
יזהה מה **רואים בתמונה**, ובהתראה ישלח לך **את התמונה של הפריט שמתאים** עם סיכום קצר ומסודר.

---

## 🔍 המצב היום (והבעיות)
| מה קורה היום | הבעיה |
|---|---|
| כל הודעה נבדקת לבד | מפרסמים שולחים 3 תמונות ואחריהן הודעה נפרדת "למסירה בחולון". התמונות נבדקות בלי הטקסט, והטקסט בלי התמונות |
| נשלחת ל-Claude רק תמונה אחת | באלבום של כמה תמונות כל תמונה נבדקת בנפרד, ומגיעות כמה התראות על אותו פריט |
| תגובות בקבוצה לא מקבלות הקשר | "נמסר" או "עדיין זמין?" נבדקות בלי הפוסט שהן מגיבות עליו |
| סרטונים נזרקים | פוסט שהוא סרטון של הפריט לא נבדק בכלל |
| ההתראה היא טקסט חופשי | אין סיכום של מה הפריט, מחיר, מיקום ומצב, ולא ברור איזו תמונה רלוונטית |
| אין זיכרון | אותו פריט שמתפרסם שוב (או בכמה קבוצות) מייצר התראה כפולה |

## 🏗️ הפתרון: 5 שלבים

### שלב 1: איחוד הודעות לפוסט אחד (הכי חשוב)
**קובץ חדש:** `src/postBuffer.js`

- מחזיקים "פוסט פתוח" לכל צמד **(קבוצה, שולח)**.
- כל הודעה חדשה מאותו שולח מצטרפת לפוסט, וטיימר ההמתנה מתאפס.
- אחרי **45 שניות** בלי הודעה חדשה מהשולח, הפוסט "נסגר" ונשלח לבדיקה.
- פוסט נסגר מוקדם אם הוא הגיע ל-**6 תמונות**, או אם הגיעה הודעת טקסט ארוכה אחרי תמונות (סימן שהפוסט הושלם).
- אלבום (`msg.type === "album"`) והתמונות שבו נכנסים לאותו פוסט.
- מבנה פוסט:
  ```js
  { groupName, sender, messages: [msg...], texts: ["..."], images: [{mimetype, data, msgId}], quoted: {...} | null }
  ```

> הפשרה: התראה מגיעה באיחור של עד ~45 שניות, וזה המחיר של הבנת הפוסט המלא. זמן ההמתנה יהיה ניתן לשינוי ב-`config.js` (`postWindowSeconds`).

### שלב 2: הקשר של תגובות (Quoted messages)
**עדכון:** `src/index.js`, `src/postBuffer.js`

- אם להודעה יש `msg.hasQuotedMsg`, טוענים את ההודעה המצוטטת (`msg.getQuotedMessage()`) ומצרפים את הטקסט שלה (ואת התמונה אם יש) כ"הקשר" לפוסט.
- Claude מקבל הוראה ברורה: ההקשר הוא רק רקע. התאמה נחשבת רק כשמישהו **מציע** פריט.
- **בונוס:** אם מישהו מגיב "נמסר" / "נמכר" / "לא רלוונטי" לפוסט שעליו כבר קיבלת התראה, תקבל עדכון "❌ הפריט כבר נמסר".
  כדי שזה יעבוד, שומרים את מזהה ההודעה של כל פוסט שהתריע (ראה שלב 5).

### שלב 3: הבנת התמונות
**קובץ חדש:** `src/media.js`

- הורדה של **כל** התמונות בפוסט (עד 6), לא רק הראשונה.
- **הקטנה** של כל תמונה לצלע ארוכה של עד 1568px בעזרת `sharp`. זה מקטין עלות וזמן, ונשאר בתוך המגבלה של 5MB.
- **סרטונים:** משתמשים בתמונה הממוזערת (thumbnail) שווטסאפ שומר בהודעה, בלי להוריד את הסרטון.
- מדבקות (stickers) ותמונות פרופיל: מתעלמים.
- כל תמונה נשלחת ל-Claude עם תווית מספרית ("תמונה 1", "תמונה 2"...) כדי שיוכל להצביע על התמונה הרלוונטית.

### שלב 4: תשובה מובנית מ-Claude
**עדכון:** `src/matcher.js`

מרחיבים את הסכמה (structured output) כך ש-Claude מחזיר תיאור של הפריט ולא רק כן או לא:

```js
{
  is_offer: true,                 // האם זו הצעה (מסירה/מכירה) ולא בקשה
  item: {
    name: "ספה תלת מושבית",
    description: "ספת בד אפורה, נראית במצב טוב",   // משלב טקסט + מה שרואים בתמונה
    price: "חינם" | "350 ₪" | null,
    location: "חולון" | null,
    condition: "טוב" | null
  },
  matches: [
    {
      id: 3,                       // מספר החיפוש
      reason: "ספה אפורה, חינם, באזור המרכז",
      image_indexes: [1, 3],       // התמונות שבהן רואים את הפריט שמתאים
      confidence: "high" | "medium" | "low"
    }
  ]
}
```

- **פוסט עם כמה פריטים** ("מוסרת ספה, שולחן ו-3 כסאות"): כל התאמה מצביעה על התמונות שלה.
- **`confidence`:** בהתאמה של `low` ההתראה תסומן "🤔 אולי", ואפשר יהיה לכבות התראות כאלה ב-config.
- עדכון הפרומפט: לזהות פריט מתוך התמונה גם כשהטקסט הוא רק "למסירה", ולסמן כש"התמונה לא מראה בבירור".

### שלב 5: התראה חכמה + מניעת כפילויות
**עדכון:** `src/index.js`, `src/store.js`

**ההתראה החדשה:**
1. תמונת הפריט הרלוונטית (לפי `image_indexes`), עם הסיכום ככיתוב:
   ```
   🎯 ספה תלת מושבית — חינם
   📍 חולון · מצב: טוב
   🔎 מתאים ל: "ספה עד 800 ש״ח" (ספה אפורה, חינם, באזור המרכז)
   👥 מסירות גוש דן · 👤 דנה (wa.me/9725...)
   ```
2. שאר התמונות הרלוונטיות, אם יש.
3. העברה של הפוסט המקורי הופכת לאופציונלית (ברירת מחדל: כבוי, כי התמונה כבר נשלחת).

**מניעת כפילויות** (`data/state.json`, נשמר 7 ימים):
- טביעת אצבע לכל פוסט שהתריע: **שולח + שם הפריט**, וגם hash של הטקסט.
- פוסט זהה (אותו פריט מאותו שולח, גם בקבוצה אחרת) לא שולח התראה חדשה. במקום זה נשלחת שורה קצרה: "↪️ פורסם שוב גם ב-X".
- שמירה של `msgId → wantId` לכל התראה, בשביל הבונוס של "נמסר" משלב 2.

## 🧪 בדיקות
1. **בדיקות יחידה (בלי ווטסאפ ובלי AI):**
   - buffer: 3 תמונות ואז טקסט מאותו שולח יוצרים פוסט אחד. שני שולחים במקביל יוצרים שני פוסטים. סגירה אחרי זמן ההמתנה.
   - כפילויות: אותו פוסט פעמיים מייצר התראה אחת.
2. **ספריית דוגמאות** `test/fixtures/`: 15–20 פוסטים אמיתיים מהקבוצות (תמונה + טקסט, בלי מספרי טלפון).
   הסקריפט `npm run try` מריץ אותם מול Claude ומדפיס מה זוהה, כדי לראות איכות לפני הפעלה אמיתית.
   מקרים שחייבים לכסות: תמונה בלי טקסט · אלבום · כמה פריטים בפוסט · "מחפש/ת..." · "נמסר" · מחיר מעל התקציב · סרטון.
3. **הרצה אמיתית במצב צל:** יום אחד שבו ההתראות נכתבות רק ללוג. בודקים כמה התאמות פוספסו וכמה היו שגויות, ומכוונים את הפרומפט.

## 💰 עלות
- תמונה אחרי הקטנה עולה בערך 1,500 טוקנים. פוסט של 3 תמונות הוא ~5,000 טוקנים, כלומר בערך 2 סנט במודל הנוכחי.
- **חיסכון שכבר מובנה בתוכנית:** איחוד לפוסט חוסך בדיקה נפרדת לכל תמונה, ההקטנה מקטינה כל תמונה, וכשאין חיפושים או כשההתראות מושהות אין בכלל קריאות.
- **אפשרות נוספת אם יהיה יקר:** בדיקה דו-שלבית, שבה קודם רק הטקסט נבדק ב-Claude Haiku ("האם זה בכלל פוסט מסירה/מכירה?"), והתמונות נשלחות רק אם כן.
